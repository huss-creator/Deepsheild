# Forensic module validation (synthetic ground truth)

Generated by `python manage.py benchmark_forensics --seed 0 --write-docs docs/forensic_validation.md`.

**What this is:** a sanity benchmark. Public-domain real photographs (scikit-image test images,
384x384 crops) are manipulated programmatically (splice, resample, inject periodic artefacts, clone),
the shipped modules are run on files, and FPR/TPR are measured at the level each module reports
(anything above LOW counts as flagged).

**What this is not:** a measurement of real-world performance. The photographs are few, the
manipulations are simple and synthetic, and there is no real deepfake/camera-pipeline diversity.
Use it to compare code versions and to see where a module is weak, not to quote accuracy.

| Module | n untouched | n manipulated | FPR | TPR | score AUC |
|---|---|---|---|---|---|
| ELA (JPEG splice) | 24 | 30 | 0.33 | 0.47 | 0.63 |
| Resampling | 18 | 48 | 0.11 | 0.46 | 0.72 |
| Frequency (artefact saved as PNG) | 18 | 12 | 0.17 | 0.92 | 0.95 |
| Frequency (artefact saved as JPEG) | 18 | 12 | 0.17 | 0.08 | 0.46 |
| Copy-move (clone) | 12 | 24 | 0.17 | 0.67 | 0.76 |

Reading it: a useful indicator needs a low FPR and a clearly higher TPR. Modules with weak
separation are capped at MEDIUM in the code and presented as low-reliability supporting
indicators. Frequency artefacts saved as JPEG are expected to be missed: JPEG's own 8x8 grid
shares those frequencies, so they are excluded to avoid false alarms.
